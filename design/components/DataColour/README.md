How a colour from the user's data, such as a calendar's colour, may appear: as a small dot or a thin bar beside the name it belongs to.

- Calendars bring their own colours from macOS or iCloud. These belong to the user, not the theme: any hue, and some fail contrast on `surface` or in dark mode. So they appear in two shapes only.
- **Dot:** an 8px circle. In a list row it sits where the icon tile would, centred in an `icon-tile` square, so names line up with rows that have tiles. A MonthGrid cell under 600px uses dots too.
- **Bar:** `space-1` (4px) wide with `radius-pill`, as tall as the text it marks. It is used in EventRow and in MonthGrid cells.
- **Never** a fill behind text, a text or icon colour, a chip, a button, a control's border, or a selected or focused state. Selection and focus use the theme's tokens.
- **Never the only signal.** The calendar's name can always be found without the colour. In a list row and in an EventRow it is next to the colour or in the row's caption. A MonthGrid cell is the one place where the name is one step away, because a cell has room only for a bar and a title, or for dots. There, the selected day's EventRows, listed beside or under the grid, always show the calendar's name in their caption, and each cell's accessible name names the calendars of its events. Two calendars with the same colour, or a colour the user cannot tell apart, lose nothing.
- Because a data colour never sits behind text and never carries meaning alone, it cannot break the text contrast rules. It is drawn exactly as the source gives it, in both modes: no lightening, darkening or theme tint. Any alpha in the value is ignored, and the colour is drawn opaque.
- **Edge:** when the colour has less than 3:1 contrast with the ground it sits on in the current mode (`surface`, `accent-soft` on a selected row or day, `surface-sunken`), it gets a 1px inner edge in `line-strong`. A yellow dot on white or a black bar in dark mode then still shows its shape, so a day's dots never vanish.
- A calendar with no colour uses `line-strong`.
- It has no accessible name. The name beside it carries the meaning.
- **The calendar list** shows or hides calendars on this device only. It has one GroupedList per source, headed by the same name for the source that the Notice and ContactHeader use, with a capital at the start: "This Mac", "iCloud account you@example.com". Each row has the dot, the calendar's name in `body-strong`, and a Switch named "Show" and the calendar's name. A hidden calendar keeps its row and its dot.
- **Sources and accounts.** A source is the way myData reads calendars, not an account. This Mac reads every calendar macOS has, whatever account it belongs to: iCloud, Google, Exchange, calendars stored only on the Mac, subscriptions and Birthdays. All of them share the Mac's range (Notice). An iCloud account source reads that one account directly, with no range: every date is read. In the This Mac group, each row has a `caption` line naming the account the calendar belongs to on the Mac, as macOS names it ("iCloud", "Google", "Exchange"). Three cases get myData's own words, because macOS calls the last two "Other": calendars stored only on the Mac say "Only on this Mac", the Birthdays calendar says "Birthdays from Contacts", and subscribed calendars say "Subscribed". A source that reads one account needs no caption, because its heading names the account.
- **The same calendars through two sources.** When This Mac and a followed iCloud account are both on, that account's calendars arrive twice, once through each source, and myData cannot reliably match them. Both copies are listed, each under its source, and the user can hide either. Settings, Sources says that following an iCloud account is not needed on a Mac that has that account.
- You provide the colour as the host gives it and the name it belongs to. For the calendar list, also each calendar's source and, under This Mac, its account.
