How fields are laid out in an editing form: one labelled field per row, rows that repeat (several phone numbers), adding and removing them, and where errors go. The contact and event editors are built from it.

- **Use it** for any form that edits a record and is saved as a whole: a contact, an event, an import's settings. **Do not use it** for settings that apply at once (GroupedList rows with Switches), for a one-field form in a dialog (the field alone), or to show a record (FieldRow is the read-only view; a form mirrors its groups and order, so switching to Edit moves nothing).
- **Save and Cancel are not part of it.** They belong to whatever holds the form: the Inspector on desktop, its editor Sheet on a phone, or a Dialog. So does asking "Discard changes?" when the user leaves with unsaved edits.

- **The form** is a column of groups, each headed by its name in the `label` style and `ink-muted` ("Phone", "When"), `space-6` from the group before. Where it sits decides its ground:
  - **in an Inspector, Sheet or Dialog** (the contact and event editors), the groups sit straight on the panel, with no cards, as the Inspector spec says: the panel is already a surface, and a card on it would be a card on a card. Fields are `space-4` apart (Inspector);
  - **on a page's `bg`** (a step of the import flow), each group is a GroupedSection with one content part (`surface`, `radius-lg`, `shadow-1`, `space-5` padding), at most `content-max` wide, with fields `space-5` apart as that spec says;
  - groups follow the read-only view's order (for a contact, FieldRow's: Phone, Email, Address, Birthday, Links, Notes, after the name), so the user finds a field where they last saw its value. Unlike the view, an editing form shows a group even when it is empty, holding only its Add button.
- **Labels are stacked, everywhere:** the label above the control in the `label` style and `ink`, `space-2` above it, as TextField. Fields stack at the spacing of their ground (above). This holds on desktop and on a phone, in an Inspector, a Sheet, a Dialog and on a page; there is no label-column layout.
  - Labels have no colon.
  - Help and error text sit under the control, starting where the control starts.
  - **A group that holds one field** (Groups, Notes, Calendar) shows no label of its own: the group's heading names it and is its accessible name.
- **A repeatable row** holds one value of a kind that can have several (phone, email, address):
  - in one line: the label Select (Mobile, Home, Work, Other, a custom label), the value field, and a remove button, `space-2` apart. The label Select is as wide as its longest preset; the value field takes the rest.
  - The label Select stays beside the value: a kind's label belongs to its value, and the group heading already names the kind.
  - An address's value is several fields (street, city, postcode, country), stacked `space-2` apart in the value's place, in the order the locale writes them; the label Select and the remove button stay on the first line.
  - Rows of one kind are `space-3` apart.
- **The remove button** is the IconButton in its danger tone: a `control-height` circle, a minus-in-a-circle icon in `danger`, `danger-soft` on hover, its accessible name and tooltip naming what it removes ("Remove mobile number"). It asks nothing: the row goes at once, and Cancel brings it back, because nothing is removed until Save. The rows close up, and focus moves to the next row's value, or the previous one's, or the Add button.
- **The Add button** sits under the last row of its group, aligned with the rows' start: a plain button with a plus icon, "Add phone", "Add email", "Add address". It adds a row with the next preset label not yet used (Mobile, Home, Work, Other, then Other again) and puts focus in its value. A row still empty on Save is dropped, never reported as an error.
- **Rows cannot be reordered** here. The order is the order the values were added, which is the order the vCard keeps.
- **A switch in a form** (All-day) is a row with its title at the start and the switch at the end (Switch, "In a form"). **A checkbox** in a form stacks like a field (Checkbox).

- **Validation:**
  - A field is checked when the user leaves it and when Save is pressed, never while it is first being typed. Once a field shows an error, it is checked again on every change and the error goes as soon as the value is right.
  - The error replaces the field's help, in `caption` and `danger`, with the 2px `danger` border, as TextField. It says what is wrong and what a correct value looks like: "That email address is incomplete. It looks like name@example.org."
  - A rule about the form as a whole (a contact needs at least a name, a company, a phone number or an email) shows its error once, at the top of the first group, in `caption` and `danger` after an alert icon at `icon` size, `space-2` apart, and only after Save is pressed. It belongs to no one field, so when it is the only error, focus moves to the message itself (focusable by script, not a Tab stop), and it is also the description of the first field of the first group.
  - Pressing Save with errors saves nothing: focus moves to the first field in error (or to the form's message, above), scrolled into view, and screen readers hear "Not saved. 1 field needs attention." assertively, because it answers the user's own press. The Save button is never disabled for errors, so the user can always press it and find out what is wrong.
  - Fields are optional unless a rule says otherwise; required fields are not marked with asterisks. The few that are required say so in their help text.
- **States** of each control are its own component's (TextField, Select, TokenField, Switch, Checkbox): hover, pressed, focused with the `focus` ring, disabled at 45% with the reason as help, error. A whole form that cannot be edited is not a disabled form: the record opens read-only (FieldRow) with the reason in a Notice.
- **Keyboard:** Tab goes through the form in reading order: within a repeatable row, the label Select, the value, the remove button; after a group's rows, its Add button. Return in a single-line field does not save, because a long form is easy to submit by accident: the holder's shortcut does (⌘S or ⌘Return in an Inspector), and in a Dialog Return confirms (Dialog spec). Escape closes anything open first, then reverts a field's own uncommitted typing where the field has one (DatePicker, TimePicker, a custom label), then is the holder's Cancel (platforms.md, "Which handler gets a key first").
- **Screen readers:** each group is a group named by its heading. A repeatable value reads its label and kind ("Mobile, phone number"); its label Select reads "Label for phone 1, Mobile". Adding and removing are announced politely ("Phone number added", "Mobile number removed"). An error reads with its field, as the field's hint.
- **Motion:** an added row opens from no height and fades in over `base` with the `standard` curve; a removed row fades and closes over `base`. With reduced motion, rows appear and go with a `fast` fade and the form jumps to its new height. Focus moves at once, not after the motion.
- **Light and dark, every theme:** only tokens; the form adds no colour of its own.
- **Phone (under 600px):** stacked, one column, straight on the Inspector's sheet with `space-4` padding across, so a repeatable row keeps its value field usable (on a page's `bg`, the groups' content parts take `space-4` padding instead of `space-5` for the same reason). `body` at 16px. The holder scrolls the focused field above the keyboard.
- **Sizes:** controls `control-height`; in the compact density (when built) `control-height-compact`.
- **Copy:** labels are nouns in sentence case with no full stop or colon ("First name", "Starts", "Time zone"). Add buttons are "Add" and the kind ("Add phone"). Help and errors are full sentences with full stops. A remove button's name says which value ("Remove work email").
- **Used by:**
  - myContacts edit contact (phase 3): name fields (First name, Last name, Company), then Phone, Email and Address with repeatable rows, Birthday, Groups (TokenField), Notes (multi-line TextField).
  - myCalendar edit event (phase 6): Title and Location; When: All-day (Switch in a form), Starts, Ends, Time zone and Repeat (Select); Calendar (Select with dots); Notes.
  - myData import (phase 4): the step that chooses which address book or calendar the import goes into.
- **Token needed:** none.
- **Decided 2026-10-14:** labels are stacked above fields everywhere. One layout to build and test, the same as TextField and GroupedSection; a contact form is about a third taller than with a label column beside the fields, which could be added later without changing anything else here.
